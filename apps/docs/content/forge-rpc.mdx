# Forge RPC

Forge RPC is how one forge backend calls another: typed request-response calls over HTTP. A service declares routers with decorators, `archlast-forge codegen` writes their types, and a caller gets `.query()` and `.mutate()` checked against them. Calls go through Nest's `ClientProxy`, like any other [microservice transport](nest.html#microservices).

Use it between forge backends, such as the services of a [monorepo](monorepo.html), where it is the default transport. To reach something that isn't a forge backend, or for events rather than calls, use one of Nest's transports.

## Backend to backend only

Forge RPC connects the `forge/` code of one backend to the `forge/` code of another. Frontends never use it: not the pages of a web app or a full-stack app, not a mobile app, not a desktop app. They call their own backend's functions with the [client](clients.html), and that backend's functions call the service:

```
web page, mobile or desktop app ──client──▶ main app's forge/ (controller or action ▶ OrdersService) ──Forge RPC──▶ orders' forge/
```

The token every backend shares, `FORGE_RPC_TOKEN`, never leaves the servers, and two checks keep it that way:

- **Codegen** (`dev`, `build`, `typecheck`) fails when frontend code imports `@archlast/forge-runtime/nest/rpc` or `forge/_generated/rpc`. Frontend code is `src/` in a backend with its own bundler, and `app/` in a full-stack app.
- **`ForgeRpcClient` and `ForgeRpcServer`** refuse to be made where there is a `window`: a browser, React Native, a Tauri page.

Everything comes from `@archlast/forge-runtime/nest/rpc`, including `z` (Zod 4). Your code imports nothing else for it.

## A router

```ts
// apps/orders/forge/orders.router.ts
import { internal } from "./_generated/api";
import type { ActionCtx } from "@archlast/forge-runtime/nest";
import { Ctx, Input, Mutation, Query, Router, z } from "@archlast/forge-runtime/nest/rpc";

const order = z.object({ id: z.string(), status: z.enum(["open", "paid", "shipped"]), total: z.number() });

@Router({ alias: "orders" })
export class OrdersRouter {
  @Query({ input: z.object({ id: z.string() }), output: order })
  get(@Input("id") id: string, @Ctx() ctx: ActionCtx) {
    return ctx.runQuery(internal.orders.byId, { id });
  }

  @Mutation({ input: z.object({ userId: z.string(), items: z.array(z.object({ sku: z.string(), qty: z.number().int().positive() })) }), output: order })
  create(@Input() input: { userId: string; items: { sku: string; qty: number }[] }, @Ctx() ctx: ActionCtx) {
    return ctx.runMutation(internal.orders.create, input);
  }
}
```

- **`@Router({ alias })`** makes the class a router. Its procedures are called as `<alias>.<method>` (`orders.get`). The alias defaults to the class name without `Router`, with its first letter lowercased. The class is also a Nest controller, so dependency injection, guards, pipes and interceptors work as usual.
- **`@Query()` and `@Mutation()`** take `input` and `output`, both Zod schemas or any other [Standard Schema](https://standardschema.dev).
  - `input` is checked before the method runs. Without it, the procedure takes no input; use `z.object({})` for one that takes an empty object.
  - `output` is checked against what the method returns. Without it, nothing is checked and callers get `unknown`: add one to type the result for them.
- **`@Input()`** receives the checked input, and `@Input("id")` one field of it.
- **`@Ctx()`** receives an anonymous `ActionCtx`, as for any microservice message: a call between services has no signed-in user. To act for a user, pass their id in the input. `@TransportCtx()` gives a `ForgeRpcContext`, which has `getPattern()` and `getRequestId()`.

Put routers in files of their own, not in `forge/http.ts`: codegen reads them from there.

## Serving it

List the routers in `nest()`'s controllers, and add a `ForgeRpcServer`:

```ts
// apps/orders/forge/http.ts
import { httpRouter } from "@archlast/forge-runtime";
import { nest } from "@archlast/forge-runtime/nest";
import { ForgeRpcServer } from "@archlast/forge-runtime/nest/rpc";
import { OrdersRouter } from "./orders.router";

const http = httpRouter();
nest(http, { controllers: [OrdersRouter], microservices: [{ strategy: new ForgeRpcServer({ port: Number(process.env.ORDERS_RPC_PORT ?? 4001) }) }] });
export default http;
```

- **Where it runs:** the server listens on its own port, in the first function runtime process, as every transport does. `host` defaults to `0.0.0.0`, so other containers can reach it.
- **The token:** every call carries a bearer token, and the server checks it. The token is `FORGE_RPC_TOKEN` unless you pass `token`, and it must be at least 16 characters. A server without one refuses to start. A client is often made as its module loads (a class field, `ClientsModule.register()`), so it reads its token at its first call, and each call fails with `UNAUTHORIZED` until the token is there. Every app that serves or calls Forge RPC needs the same value.
- **Startup checks:**
  - A router whose alias isn't an identifier, or one without a procedure, fails when its module loads.
  - A `ForgeRpcServer` that can't start, because it has no router to serve or its port is taken, logs `[forge-rpc] the server didn't start: …`, and the app's Nest routes answer with that error.
- **Other transports:** router methods are registered under Forge RPC's own transport id. Other transports in the same app don't serve them, and Forge RPC doesn't serve `@MessagePattern` handlers.

## Its types: forge/_generated/rpc.ts

`archlast-forge codegen` (run by `dev` and `typecheck`) writes what the routers serve:

```ts
// apps/orders/forge/_generated/rpc.ts
export interface Rpc {
  /** orders.router.ts: OrdersRouter */
  orders: {
    get: { kind: "query"; input: { id: string }; output: { id: string; status: "open" | "paid" | "shipped"; total: number } };
    create: { kind: "mutation"; input: { userId: string; items: Array<{ sku: string; qty: number }> }; output: { id: string; status: "open" | "paid" | "shipped"; total: number } };
  };
}
```

- **How it's built:** codegen imports the files that contain `@Router(`, in a process of its own, and turns each schema into a type through JSON Schema. Input types are what the schema accepts, output types what it returns. A procedure without an output schema gets `unknown`, and codegen says so: reading its method's return type would put the service's own generated types into the caller's TypeScript project, where two backends' schemas collide.
- **Its limits:** a value JSON Schema can't describe (a `Date`, a transform) becomes `unknown`, and a recursive schema stops at `unknown` too. Answers travel as JSON, so a `Date` reaches the caller as a string.
- **Duplicates:** two routers with the same alias fail codegen.

The file is committed like the rest of `forge/_generated`. In a monorepo, `packages/contracts` re-exports it for the backends that call the service (`export type { Rpc as OrdersRpc } from "../../apps/orders/forge/_generated/rpc"`).

## Calling it

Calls come from another backend's `forge/` code. By default they live in a class: a Nest service that holds the typed client. The app's controllers, actions and other services all go through that class, so the app has one client per service and one place that knows the service's address.

### A service class that makes the calls

```ts
// apps/web/forge/orders.service.ts
import { Injectable } from "@archlast/forge-runtime/nest";
import { createForgeRpcClient } from "@archlast/forge-runtime/nest/rpc";
import type { OrdersRpc } from "@acme/contracts";

/** Calls the orders service. One instance for the app, so one client. */
@Injectable()
export class OrdersService {
  private readonly orders = createForgeRpcClient<OrdersRpc>({ url: process.env.ORDERS_RPC_URL ?? "http://127.0.0.1:4001" });

  async checkout(userId: string, items: { sku: string; qty: number }[]) {
    const order = await this.orders.orders.create.mutate({ userId, items });
    return this.orders.orders.get.query({ id: order.id });
  }

  status(id: string) {
    return this.orders.orders.get.query({ id });
  }
}
```

- **How a call reads:** `this.orders.orders.create.mutate(...)` is the client, then the router's alias, then the procedure. `.query()` exists only on queries and `.mutate()` only on mutations, and both are typed from the schemas. TypeScript catches a wrong argument or a renamed procedure, and the result has the procedure's output type.
- **One client per app:** Nest makes the class once, so it has one client. Calls made in the same tick, from any request, share one HTTP request.
- **Options:** `createForgeRpcClient` takes `{ url, token?, timeoutMs? }`. `token` defaults to `FORGE_RPC_TOKEN`, and `timeoutMs` to 5000.
- **No checks in the caller:** the service checks input and output itself, so nothing is validated twice.
- **Where to call it from:** controllers, actions and other services. Not queries or mutations: they run in a database transaction, a mutation can run more than once, and neither may do I/O (see [Functions](functions.html)).

### From a controller

The service class goes in `providers`, and anything that needs it takes it in its constructor:

```ts
// apps/web/forge/checkout.controller.ts
import { Body, Controller, Get, Param, Post } from "@archlast/forge-runtime/nest";
import { OrdersService } from "./orders.service";

@Controller("checkout")
export class CheckoutController {
  constructor(private readonly orders: OrdersService) {}

  @Post()
  checkout(@Body() body: { userId: string; items: { sku: string; qty: number }[] }) {
    return this.orders.checkout(body.userId, body.items);
  }

  @Get(":id")
  status(@Param("id") id: string) {
    return this.orders.status(id);
  }
}
```

```ts
// apps/web/forge/http.ts
nest(http, { controllers: [CheckoutController], providers: [OrdersService] });
```

`POST /http/checkout` and `GET /http/checkout/:id` now call the orders service. Import the service class as a value, not with `import type`: Nest reads the constructor's parameter types to know what to inject. Another provider, a `PaymentsService` say, takes `OrdersService` in its constructor the same way.

### From an action

An action can call the route too. It gets the same instance with `inject(ctx, OrdersService)`:

```ts
// apps/web/forge/checkout.ts
import { action, v } from "@archlast/forge-runtime";
import { inject } from "@archlast/forge-runtime/nest";
import { OrdersService } from "./orders.service";

export const checkout = action({
  args: { userId: v.string(), items: v.array(v.object({ sku: v.string(), qty: v.number() })) },
  handler: async (ctx, { userId, items }) => (await inject(ctx, OrdersService)).checkout(userId, items),
});
```

- **For the app's own frontend:** pages call `api.checkout.checkout` as they call any function, typed from the procedure's output. The frontend reaches the service only through its own backend.
- **From a cron or the scheduler:** the same action works, since a scheduled action runs like any other.
- **Its own client:** an action can also make a client at the top of its module (`const orders = createForgeRpcClient<OrdersRpc>({ url })`) and call it directly. The service class is the default because it keeps one client per app and one place for the address, and because controllers and actions then share it.

### With ClientsModule

To register the transport the way Nest registers any microservice client, inject a `ForgeRpcClient` with `ClientsModule` and wrap it. `ClientsModule.register()` makes the client when the module file loads, and Nest closes it when the app stops:

```ts
// apps/web/forge/orders.module.ts
import { Inject, Injectable, Module } from "@archlast/forge-runtime/nest";
import { ClientsModule, type ClientProxy } from "@archlast/forge-runtime/nest/microservices";
import { createForgeRpcClient, ForgeRpcClient, type ForgeRpcClientOf } from "@archlast/forge-runtime/nest/rpc";
import type { OrdersRpc } from "@acme/contracts";

@Injectable()
export class OrdersService {
  private readonly orders: ForgeRpcClientOf<OrdersRpc>;

  constructor(@Inject("ORDERS") client: ClientProxy) {
    this.orders = createForgeRpcClient<OrdersRpc>(client);
  }

  status(id: string) {
    return this.orders.orders.get.query({ id });
  }
}

@Module({
  imports: [ClientsModule.register([{ name: "ORDERS", customClass: ForgeRpcClient, options: { url: process.env.ORDERS_RPC_URL! } }])],
  providers: [OrdersService],
  exports: [OrdersService],
})
export class OrdersModule {}

// forge/http.ts: nest(http, { imports: [OrdersModule], controllers: [CheckoutController] })
```

The injected client is a plain `ClientProxy` too. `client.send("orders.get", { id })` works as with any transport, for a query or a mutation, and its observable errors with the plain [error envelope](#errors). `emit()` fails: Forge RPC is request-response only.

## Errors

A failed call answers in the engine's [error envelope](errors.html), `{ message, code, data?, requestId? }`:

| What happened in the service | `code` | The caller gets |
|---|---|---|
| The method threw a `ForgeError` | `BAD_REQUEST`, with its `data` | a `ForgeError` with the same data, which reaches this app's own caller as the service meant |
| The method threw an `RpcException` | `BAD_REQUEST` | a `ForgeError` with its message |
| The input failed its schema | `BAD_REQUEST` | a `ForgeError` with the schema's issues |
| Anything else, or an output that failed its schema | `INTERNAL_SERVER_ERROR` | a `ForgeRpcError`, "Server error (request …)" |
| A wrong or missing token | `UNAUTHORIZED` | a `ForgeRpcError` |
| No procedure by that name | `NOT_FOUND` | a `ForgeRpcError` |
| No answer within `timeoutMs` (5 s) | `TIMEOUT` | a `ForgeRpcError` |
| The service can't be reached | `SERVICE_UNAVAILABLE` | a `ForgeRpcError` |

- **What never leaves the service:** stack traces, SQL, and the message of an unexpected error. The service logs the whole error with the request id it sends back (`[forge-rpc] orders.get failed (request …)`).
- **Timeouts:** a `TIMEOUT` on a mutation means the outcome is unknown, because the service may still finish it.
- **Raw `send()`:** the observable errors with the plain envelope object, as Nest transports do.

## On the dashboard

Each call is a request of the service that served it, of kind `rpc`, named by its pattern (`orders.place`), with its latency, errors and the classes it ran as its spans. The client's call carries the caller's trace, so a request to the main app and the calls it made to services are one trace, and the [map](observability.html#the-pages) draws the link between them. With the services reporting to the main app's [one dashboard](observability.html#one-dashboard-for-a-main-app-and-its-microservices), that trace is on one page.

## Performance

- **Calls made in the same tick** go out as one HTTP request (batches of up to 32), over kept-alive connections. Every call is a POST, so a large query input never goes in a URL.
- **The server** is a `Bun.serve` of its own, about 1.8× faster than serving the same calls through Node's `http` module on Bun. Its body limit is `MAX_REQUEST_BYTES`.

`bun benchmarks/forge-rpc/bench.ts` compares it with Nest's TCP transport. It uses one engine and 64 concurrent callers sending through `ClientProxy`, on a 4-core AMD EPYC with Bun 1.4.4, and `BENCH_REDIS_URL` adds Redis. These are two runs:

| Payload | TCP | Forge RPC |
|---|---|---|
| 16 bytes | 17,600 to 19,000 calls/s (p50 2.9 ms) | 4,600 to 5,000 calls/s (p50 9 to 10 ms) |
| 64 KB | 780 to 1,080 calls/s | 850 to 930 calls/s |

TCP's framing beats HTTP on small messages, and with 64 KB payloads the two are even. Forge RPC buys typed, validated calls and errors that keep their meaning. For a hot path between two services that exchange tiny messages, measure before choosing it.

## Moving a pattern from TCP

1. **Make the controller a router.** Replace `@Controller()` with `@Router({ alias: "orders" })`, and `@MessagePattern("orders.get")` with `@Query({ input, output })` on a method named `get`.
2. **Take the input from `@Input()`.** Use it where the method took `@Payload()`, and move the checks the method did by hand into `input`.
3. **Serve it.** Add `{ strategy: new ForgeRpcServer({ port }) }` to `microservices`. TCP can keep listening beside it, so callers can move one at a time.
4. **Switch the callers.** Run codegen. In the class that sends the message, replace its `ClientProxyFactory` client with `createForgeRpcClient<OrdersRpc>({ url })`, and `client.send("orders.get", data)` with `this.orders.orders.get.query(data)`.
5. **Share the token.** Set the same `FORGE_RPC_TOKEN` in both apps.
