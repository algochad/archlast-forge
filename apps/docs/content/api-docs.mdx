# API docs and OpenAPI

The engine describes the app's API as an OpenAPI 3.1 document and serves it with a docs page where every operation can be read and tried. The document is made from the code that runs: the public queries, mutations and actions, the routes in `forge/http.ts`, and the NestJS controllers, with request and response schemas taken from the same validators the engine checks calls against. Nothing is written by hand, so it can't drift. What validators can't say (the API's name, its authentication, its errors, the webhooks it sends, who the docs are for) is configured in code next to the routes.

It works as an app's public REST reference: one setting leaves the reactive functions out, the document states the app's real authentication and error shape, and the page can be served in production at a path of your choosing, beside your own pages.

## Turning it on

With no configuration the docs are at `/_api` in development and off in production, as before:

| Path | What |
|---|---|
| `/_api` | The docs: the overview, your guides and the reference, a page each, rendered on the server, with "Try it" on every operation. |
| `/_api/<tag>/<operation>`, `/_api/guides/<slug>`, … | A page of the docs ([Pages and addresses](#pages-and-addresses)). |
| `/_api/<page>.md`, `/_api/index.md`, `/_api/llms.txt` | Each page as Markdown, and the index of them ([Markdown and llms.txt](#markdown-and-llmstxt)). |
| `/_api/openapi.json` | The document: minified, compressed (brotli or gzip, as the client accepts), with an `ETag`. |
| `/_api/explorer` | The overview with the request builder open (`?op=<operationId>` picks the operation). |

| Setting | Default | |
|---|---|---|
| `API_DOCS` | unset: the code decides | `on` or `off` wins over the code either way. |
| `API_DOCS_PATH` | unset: `http.docs({ path })`, else `/_api` | Where the page is. It can't be under a path the engine serves itself (`/rpc`, `/http`, `/_dashboard`, …). |

## Configuring the docs in code

`http.docs({...})` in `forge/http.ts` says where the docs are, who they are for, and what the document says beyond the validators. It is checked when the module loads: a security scheme or a parameter a route names that isn't declared here fails the load.

```ts
// forge/http.ts
import { httpRouter, v } from "@archlast/forge-runtime";

const http = httpRouter({ root: true });

const Problem = v.object(
  { type: v.string({ format: "uri" }), title: v.string(), status: v.number({ int: true }), detail: v.optional(v.string()), code: v.string() },
  { name: "Problem", description: "An RFC 9457 problem document." },
);

http.docs({
  // Where
  path: "/docs", // the page (default /_api)
  openapi: "/openapi.json", // the document (default <path>/openapi.json)
  explorer: "/docs/try", // the page with the request builder open (default <path>/explorer); false: no "Try it"
  basePath: "/platform", // a reverse proxy serves the app under https://example.com/platform
  production: true, // serve them in production too

  // Who for
  include: ["/api/v1"], // only paths under these prefixes
  exclude: ["/api/v1/internal"],
  functions: false, // leave out POST /rpc/<name>

  // What the validators can't say
  info: { title: "Midas API", version: "v1", description: "Accept payments. Every amount is in the smallest unit of its currency." },
  servers: [process.env.PUBLIC_URL ?? "https://api.midas.example"],
  securitySchemes: {
    oauth: {
      type: "oauth2",
      flows: { clientCredentials: { tokenUrl: "/api/auth/oauth2/token", scopes: { "payments:read": "Read payments", "payments:write": "Create and refund payments" } } },
    },
  },
  security: [{ oauth: [] }], // every route's default; a route's own wins
  errors: { schema: Problem, contentType: "application/problem+json", common: { 401: "unauthorized", 429: "rate_limited" } },
  parameters: {
    idempotencyKey: { in: "header", name: "Idempotency-Key", schema: v.string({ maxLength: 255 }), description: "Makes a retried POST safe." },
    version: { in: "header", name: "Midas-API-Version", schema: v.literal("v1"), global: true }, // on every route
  },
  headers: { "x-request-id": { description: "The request's id, for support." } }, // on every response
  tags: [{ name: "Payments", description: "Charge a customer, once or on a schedule." }],
  tagGroups: [{ name: "Core resources", tags: ["Payments", "Refunds"] }],
  webhooks: { events: { "payment.succeeded": { summary: "A payment went through.", data: Payment } } }, // Payment: a v.object({ ... }, { name: "Payment" })

  // The page
  page: { title: "Midas", logo: { url: "/logo.svg" }, theme: { accent: "#6d28d9" } },
});
```

| Field | Default | What it does |
|---|---|---|
| `path` | `/_api` | The docs page. `API_DOCS_PATH` wins. |
| `openapi` | `<path>/openapi.json` | The document. `"/openapi.json"` puts it at the root. |
| `explorer` | `<path>/explorer` | Opens the page with the request builder showing; `false` turns "Try it" off. |
| `basePath` | none | A prefix a reverse proxy adds in front of the server. URLs in the page and the document's links start with it. |
| `production` | `false` | Serve the docs in production too. `API_DOCS` wins. |
| `include`, `exclude` | everything | Path prefixes the document keeps, and drops. |
| `functions` | `true` | List the reactive functions (`POST /rpc/<name>`). `false` for a REST API's docs. |
| `info` | the package name and the release | `title`, `version`, `description` (markdown), `termsOfService`, `contact`, `license`. |
| `servers` | the address the document was asked at (`BETTER_AUTH_URL` when set) | Where requests go. |
| `securitySchemes`, `security` | the engine's session cookie and bearer token, on `/rpc` only | The app's authentication, and the default requirement. |
| `errors` | the engine's `ErrorBody` | `schema` (name it), `contentType`, and `common` errors every route can answer. |
| `parameters` | none | Reusable parameters by key; routes list the keys they take, and `global` ones are on every route. |
| `headers` | none | Headers every response carries. |
| `tags`, `tagGroups` | tags in order of appearance | Descriptions (markdown) and the navigation's sections. |
| `webhooks` | none | The events the app sends. See [Webhooks](webhooks.html#documenting-the-events-you-send). |
| `page` | | The page's title, logo, theme, code-sample languages, request builder, credentials and strings. See [The page](#the-page). |

## Who the document is for

The document served is the **public** one: what `include`, `exclude`, `functions: false` and each route's `hidden` leave. In development, `openapi.json?audience=all` is the **complete** one, with everything the public one leaves out marked `x-internal: true`, and the page has a switch between the two. A route that is served but none of an integrator's business (an inbound webhook from a provider) is hidden with `hidden: true` on `http.route()` or `@Contract()`, or `@ApiHidden()` on a Nest controller or handler.

## What a route says about itself

The schemas come from the validators: `query`, `body` and `returns` on [HTTP routes](http.html#validators-and-the-openapi-document), `params`, `query`, `body` and `returns` on [`@Contract`](nest.html#contract-validators-and-the-openapi-document). Validators carry [constraints and documentation](schema.html#constraints-and-documentation) (enums, bounds, formats, descriptions, examples, names), which the document and the page show and the engine enforces. A route adds, for the document only:

| Field | |
|---|---|
| `summary`, `description`, `tags` | What it is, and where it is listed. |
| `security` | `[{ oauth: ["payments:write"] }]`, or `[]` for none. The scopes are shown on the operation. On Nest, `@ApiSecurity(scheme, scopes)` on a handler or controller says the same, and a scope guard can apply it itself. |
| `errors` | `{ 404: "payment_not_found", 422: ["amount_too_small", { code: "currency_unsupported", description: "…" }] }`: the statuses and the stable codes, in the app's error shape. |
| `parameters` | Keys of `http.docs({ parameters })`. |
| `headers`, `responseHeaders` | Request headers it reads and response headers it sends. |
| `status`, `responseDescription` | The success status (default 200, 201 for a Nest `POST`) and what the answer is. |
| `codeSamples` | Your own snippets (an SDK call), shown before the generated ones. |
| `hidden`, `deprecated` | |
| `operationId` | The operation's id, the end of its page's address (`createProduct` is `/docs/products/create-product`) and a generated client's method name. Without one it comes from `summary` ("Create a product" is `createAProduct`), unique in the document, else from the route (`http_GET_…`, or the controller and method). |

In development the engine warns once per load about documented routes with no `returns`, no `summary` or no tags: a reader of the page would notice.

## What the document holds

- **Functions** (unless `functions: false`): `POST /rpc/<module>:<name>` for each public function, the body being its `args` and the `200` answer `{ "result": … }` with its `returns` validator. Internal functions are left out. Their errors share the engine's `ErrorBody` schema: `{ "error": { "message", "code", "data"?, "requestId" } }`, with the status codes in [Errors](errors.html), and their security is the engine's session cookie and Better Auth bearer token, both optional.
- **HTTP routes**: every `http.route()`, under `/http`, or at the root with `httpRouter({ root: true })`. An `http.route()`'s validation failure is the engine's own `400` with `ErrorBody`; its other errors are in the app's error shape.
- **NestJS controllers**: every controller method with a route, from Nest's own metadata (method and path, `:id` as `{id}`), grouped by controller unless it has tags. Its errors are in the app's error shape, since they go through your exception filters.
- **Schemas**: inline, except validators with a `name`, which are written once under `components.schemas` and referred to. Names are yours, so they don't change when another schema is added.
- **Webhooks**: the `webhooks` section, one entry per event, with the envelope, the three signature headers and an example, and `x-webhooks-signing` with the retry schedule.
- Extensions the page reads: `x-tagGroups`, `x-codeSamples`, `x-error-codes` and `x-scopes` on operations, `x-internal`, `x-webhooks-signing`.

The document is made once per load of the code: a change in dev, a reload or a restart makes the next one.

## Paths: the docs and your own pages

The docs own their page (`<path>` and `<path>/`), its assets (`<path>/_docs/…`), the explorer path and the document. Below `<path>`, they answer an address only when it is one of their pages, its Markdown or `llms.txt`, and only when none of your pages (or a root-mounted HTTP route) takes it; anything else goes to your app. So a full-stack app can have its own `/docs/blog` beside the generated reference at `/docs`. If one of your pages takes one of the docs' fixed paths, the engine logs both and your app keeps the path; in production it refuses to start, since one of the two would otherwise lose the path without a word. Move the docs with `http.docs({ path, openapi, explorer })` or `API_DOCS_PATH`.

## The page

With no configuration the page has the layout readers know from most API docs:

- **A navigation that runs the page's height**, with the logo, the name and the version at its top, search with its shortcut (`⌘K`, `Ctrl K` or `/`), groups in sentence case that fold, the current page marked, and at its foot your links, the openapi.json link and the light/dark switch (an icon).
- **A bar above the content** with the header slot, the Authorize button and, when you have them, tabs.
- **A page per topic**, at an address of its own: the overview (the API's description, its base URLs and the authentication it takes), each guide, each tag (its description and its operations), each operation, the webhooks and the models. Above the title, the section the page is in; beside it **Copy page** (the page as Markdown) and **View as Markdown**; at its end **previous and next**; on wide screens an **On this page** column that follows the reading. Headings have a link of their own.
- **An operation**: its title, an endpoint bar (method, full URL, copy, **Try it**), its description, then Authorizations (the schemes, and "Scopes:" with each scope's meaning on hover), path, query and header parameters, the body, and the responses with their error codes (their headers folded), beside a sticky column of code: your own `codeSamples` first, then cURL, Node, Python and the other languages in `page.codeSamples.languages` (one choice for every operation), and a response example per status. Samples show placeholders, never credentials.

Pages are rendered on the server, so they read without JavaScript and every address can be shared, crawled and opened in a new tab. The browser then takes the page over and moves between pages without reloading.

### Pages and addresses

| `page.layout.pages` | An operation's address | |
|---|---|---|
| `"operation"` (default) | `/docs/payments/create-payment` | A page per operation; a tag's page lists its operations. |
| `"tag"` | `/docs/payments#create-payment` | A page per tag, its operations one after another. |
| `"single"` | `/docs#payments/create-payment` | Everything on one page, as earlier releases had it. |

The end of an operation's address is its `operationId` in lowercase words. Guides are at `/docs/guides/<slug>` (the file name without a leading number), the webhooks at `/docs/webhooks`, the models at `/docs/models`. `page.layout.referencePath: "/api"` puts the reference below a path of its own (`/docs/api/payments/create-payment`), apart from the guides. An address of the single page of earlier releases (`/docs#/payments/createPayment`) moves to the page that has it now, and so do such links in your descriptions.

### Try it

Every operation has a **Try it** button in its endpoint bar that opens the request builder on that operation, in the page, filled from its schema and examples. Its script is fetched the first time someone presses the button (and prefetched when the pointer or focus reaches it), so the page's first load doesn't carry it. `<path>/explorer` (or `?try` on an operation's address) opens the page with the builder showing; `?op=<operationId>` picks the operation. `http.docs({ explorer: false })` takes "Try it" away.

**Credentials.** The page's **Authorize** panel takes the app's declared schemes: a bearer token, an API key, or OAuth2 client credentials (client id and secret in, the token fetched from the token URL, with the scopes and any extra parameters, and renewed before it ends). They are kept in `sessionStorage` (or in memory, with `page.credentials: "memory"`), sent only to the API and its token endpoint, and shared with the builder both ways. `page.explorer.auth` pre-selects a scheme and pre-fills the OAuth2 client id, scopes, token URL and extra token parameters such as RFC 8707's `resource`:

```ts
http.docs({
  page: {
    explorer: { auth: { preferredScheme: "oauth", oauth2: { scopes: ["payments:read"], extraParams: { resource: "https://api.midas.example/api/v1" } } } },
  },
});
```

The builder is the engine's fork of [Scalar](https://github.com/scalar/scalar)'s request builder: the source is a pinned Scalar release and a small patch series in `packages/dashboard/scalar/`, built by `bun scripts/update-scalar.ts` and vendored, with Scalar's MIT licence and every bundled package's in `THIRD_PARTY_NOTICES.md`. Nothing about your API leaves the server: no proxy (upstream's default proxy is patched out), no telemetry, no hosted features, no web fonts.

### Guides

Put MDX files in `forge/docs/` and each is a page. Front matter sets the title, the navigation section and the order; without it a page is titled by its first `#` heading and ordered by file name. Its `#` heading is the page's title, and its `##` and `###` headings are its "On this page":

```mdx
---
title: Accepting a payment
group: Guides
order: 1
---

# Accepting a payment

<Callout type="warning">Payments are **final** once captured.</Callout>

<Steps>
  <Step title="Create a client">In the dashboard.</Step>
  <Step title="Take a payment">Send an `Idempotency-Key` on every `POST`.</Step>
</Steps>
```

Guides can use these without importing anything:

| Component | |
|---|---|
| `<Callout type title>` | `type` is `note` (default), `info`, `tip`, `warning` or `danger`; `<Note>`, `<Info>`, `<Tip>`, `<Warning>` and `<Danger>` are the same with the type set. |
| `<Tabs group>` with `<Tab title>` | The choice is remembered, and shared by tabs with the same titles (or the same `group`). |
| `<Steps>` with `<Step title>` | Numbered steps. |
| `<Cards cols>` with `<Card title href icon>` | A grid of links or notes. |
| `<CodeGroup>` | Code blocks as tabs, titled by their `title`. |
| `<Accordion title defaultOpen>`, `<AccordionGroup>` | Folded sections. |
| ` ```ts title="server.ts" ` | A code block with a title, its language and a copy button. |

Your own components go in `forge/docs/_components/`: a `.tsx` file's default export is there by the file's name (`callout-box.tsx` is `<CalloutBox>`), and its capitalised named exports by their names. They run with the page's own React, so a backend needs nothing installed.

### Slots

Files in `forge/docs/_slots/` are not pages but places on every page: `header.mdx` (the bar above the content), `sidebar-footer.mdx` (the foot of the navigation), `operation-before.mdx` and `operation-after.mdx` (around every operation; they get `operation`, `path`, `method` and `tag` as props). Pages, slots and components are compiled when the page is first asked for (and again when a file changes), with React from the engine. They can use Markdown and JSX elements, not `import`s.

**A mistake doesn't take the page down.** A page, slot or component that doesn't compile is logged with its file and line (`✗ the API docs page: forge/docs/_slots/header.mdx:1:10: Could not parse expression with acorn`), and in its place the page shows that message in development and nothing in production; one that fails while rendering is caught the same way. The rest of the page works.

### Look

| `page` field | |
|---|---|
| `title`, `logo` | The name beside the logo (default `info.title`), and the logo: `{ url, dark?, alt?, href?, title? }`, `dark` for dark mode, `title: false` for the mark alone. |
| `theme.preset` | Where the look starts: `"default"` (warm paper, outlined method labels), `"minimal"` (white, hairline borders, light code panels, tinted method labels) or `"dark"` (dark first). |
| `theme.mode` | `"auto"` (default: follows the visitor, with a switch), `"light"` or `"dark"`. |
| `theme.tokens` | Any of the page's colours, one value or `{ light, dark }`: `bg`, `surface`, `text`, `muted`, `faint`, `border`, `borderStrong`, `accent`, `accentFill` (primary buttons), `codeBg`, `inlineCodeBg`, `ok`, `warn`, `err` (statuses and methods), `synKey`, `synStr`, `synNum`, `synLit` (JSON). `accent` sets `accent` and `accentFill` together. |

The request builder takes the page's colours and fonts. To restyle beyond the settings, use the tokens (each is the custom property `--fd-<name>`, kebab-case) and these `data-part` attributes, which stay stable; the `fd-*` classes may change:

`root`, `sidebar`, `brand`, `version`, `search`, `nav`, `nav-group`, `nav-item`, `sidebar-footer`, `footer-links`, `header`, `tabs`, `actions`, `authorize`, `theme-toggle`, `download`, `dev-switch`, `content`, `article`, `page-head`, `breadcrumb`, `page-actions`, `toc`, `pagination`, `overview`, `authentication`, `tag`, `tag-endpoints`, `operation`, `endpoint-bar`, `method`, `try-it`, `authorizations`, `scopes`, `code-panel`, `webhooks`, `webhook`, `models`, `model`, `guide`, `heading`, `callout`, `tabs`, `steps`, `cards`, `card`, `accordion`, `code-block`, `code-group`, `content-error`, `slot-header`, `slot-operation-before`, `slot-operation-after`.

To look like another docs site, start from a preset and change a few tokens:

```ts
http.docs({
  page: {
    logo: { url: "/logo.svg", dark: "/logo-dark.svg", title: false },
    theme: { preset: "minimal", code: "light", tokens: { accent: { light: "#6d28d9", dark: "#a78bfa" } } },
    nav: {
      tabs: [{ label: "Docs", section: "guides" }, { label: "API reference", section: "reference" }, { label: "Changelog", href: "/changelog" }],
      footer: [{ label: "OpenAPI document", href: "/docs/openapi.json" }, { label: "Dashboard", href: "/" }],
    },
    controls: { themeToggle: { style: "icon", place: "header" }, download: false },
    layout: { referencePath: "/api" },
  },
});
```

### Markdown and llms.txt

Every page is also Markdown at its address plus `.md` (`/docs/payments/create-payment.md`; the overview is `/docs/index.md`): an operation as its method and URL, authorizations and scopes, parameters as a table, the body's fields, the responses with their error codes, an example response and a cURL request; a guide as its own MDX without the front matter. That is what **Copy page** copies. `/docs/llms.txt` lists every page's Markdown by section, with a line about each, for tools and language models.

### In a full-stack app's own layout

A full-stack app can render the reference inside its own pages, navigation and theme instead of (or beside) the engine's page. Add `@archlast/forge-dashboard` to the app's dependencies and render `ApiReference`:

```tsx
// app/routes/developers/api.tsx
import "@archlast/forge-dashboard/api-docs/styles.css";
import { ApiReference } from "@archlast/forge-dashboard/api-docs/react";

export default function ApiPage() {
  return <ApiReference openapiUrl="/openapi.json" explorerUrl="/docs/_docs/explorer.js" config={{ theme: { accent: "#6d28d9" } }} />;
}
```

It renders on the server (pass `document` instead of `openapiUrl` to render the whole reference there) and hydrates in the browser. Its styles are scoped to the component and sit in one CSS layer, so they don't restyle the rest of your page, and your own unlayered rules win over them. `guides`, `slots` and `components` (for the guides' MDX) take React components; `explorerUrl: null` turns "Try it" off. Inside your page it shows everything on one page with `#anchor` links by default; with `config.layout.pages` set to `"operation"` or `"tag"`, pass `basePath` (where your route is) and `path` (the part after it) and render it from a catch-all route.

## Size

The page is React, bundled when it is first asked for: minified, split so guides, the Authorize panel and the code samples beyond cURL load when they are needed, and hashed and cached for a year. Its first load is about **95 KB gzipped** (the HTML shell, script, stylesheet; a page's own server-rendered HTML comes on top), plus the Geist fonts as two Latin `woff2` files (29 and 23 KB) fetched when text uses them.

The request builder is loaded only by "Try it": **812 KB with brotli** for the script and 23 KB for its stylesheet (3.4 MB raw), against 1.06 MB for the whole Scalar reference the engine used to serve on a page of its own.
